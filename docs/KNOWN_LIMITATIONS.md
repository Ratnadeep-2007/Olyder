# Current limitations and unsupported capabilities

This branch is unreleased and is not a proof of production correctness.

- No live Codex/OpenCode/Claude provider-account study, invoice API reconciliation, or provider-enforced gateway cap was run. Claude is not installed locally. CLI usage can be partial; model identity used for pricing may be requested rather than independently observed. Monetary admission is USD-only and local/soft. strict means stop on unknown settlement, not a hard spending guarantee.
- Docker is optional. Host mode requires explicit unsafe authorization for builders and is not OS isolation. Directory separation cannot protect against a hostile host process with the same rights. Local Docker Desktop's daemon was unavailable; hosted Docker tests provide separate evidence. Rootless Docker/egress proxy configurations remain unverified. Root UID/mount mappings may fail closed.
- Docker protects builder and command-check processes only. HTTP/browser checks and explicitly trusted Python verifier/provider/exporter callbacks execute on the host. No arbitrary Python plugin is automatically imported. Executable manifests currently cover agents; other Python extension types require trusted registration. There is no sandboxed general-purpose Python plugin loader.
- Source snapshots reject links/reparse points and special files, exclude known credentials, VCS/runtime metadata and dependency trees, and cap snapshots at 100 MB / 20,000 files/directories. These restrictions can require configuration migration. Custom oracle scripts/data must be declared protected; inference cannot discover every semantic oracle dependency. No comprehensive secret scanner is claimed.
- Source application is checked, but not an atomic multi-file transaction. An I/O failure can leave partial changes, reported blocked. Concurrent changes are refused. Filesystem access from deliberately unsafe host workloads remains outside this protection boundary.
- Recovery re-verifies a durable proposal; it does not blindly resume a paid or mutating request. Uncertain builder/critic phases remain blocked. --recover requires the operator to stop old work. A dead supervisor, detached host processes, PID reuse and daemon failure cannot be fully contained by best-effort cleanup. HTTP cancellation may wait for a bounded socket timeout. Deadline acceptance is fail-closed, not a hard guarantee of resource shutdown at an exact instant.
- Workspace manifests now use schema 3 to preserve directory topology and permissions. Earlier experimental schema-1/2 snapshots cannot be resumed. Spec schemas 1/2 and old direct engine functions remain supported; engine.run_loop retains the older shared-workspace boundary and should not be used for hostile tasks.
- Incremental selection is opt-in and depends on explicit mappings. Invalid/unmapped changes use full checks. Dynamic/plugin checks remain eligible; every PASS runs the full suite. There is no result cache. Policy modes change retry/time-admission defaults, not correctness or arbitrary model allocation percentages.
- The optional HTTP API is authenticated loopback read-only; no remote deployment, TLS, multi-tenant service, HTTP builder endpoint or remote MCP authorization is provided. Local MCP mutation requires server-side grants. Windows CLI script wrappers may need a native executable adapter; vendor live integrations are not certified.
- The offline pilot compares deterministic fixtures, not model intelligence or market-wide efficiency. Browser/service-dependent pilot rows are explicitly skipped. Positive actual provider billing is unknown, so no solves-per-dollar or cost-saving percentage is reported. Official Harbor/SWE-bench runs were not performed.
- Per-run environment metadata records Python/OS and adapter/provider observations, but does not independently probe every agent binary/model version. Pin these externally for live studies. Calling an arbitrary plugin with --version could itself execute untrusted code and is not done automatically.
- Local Windows lacks symlink-creation privilege: the two original fixture failures are retained. Hosted Windows/Ubuntu/macOS evidence is tracked separately. Passing declared tests is neither exhaustive security assurance nor proof that undeclared real-world requirements are fulfilled.
